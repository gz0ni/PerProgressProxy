PerProcessProxy пускает TCP-трафик **одной выбранной программы** через
SOCKS5 / SOCKS4 / HTTP-прокси. Браузер, игры, Clash и сама система продолжают
ходить напрямую. Прокси можно сменить прямо на ходу, без перезапуска
программы: новый IP выхода появляется примерно через секунду.

```
 app ──connect(example.com:443)──▶ [ proxyinject ] ──SOCKS5 / HTTP──▶ 1.2.3.4:1080 ──▶ example.com
 всё остальное ───────────────────────────────────────────────────────────────────▶ обычный маршрут
```

## Возможности

- **Только один процесс.** Затрагивается лишь тот процесс, в который внедрён
  модуль. Никаких TUN, VPN, маршрутов и правок DNS.
- **Смена на лету.** Запущенные процессы перечитывают список и настройки меньше
  чем за секунду и при ротации обрывают старые соединения.
- **Авторотация.** Смена выхода каждые N секунд или вручную по списку.
- **Fail-closed.** Если прокси не отвечает, соединение отклоняется, а не уходит
  напрямую с вашим настоящим IP.
- **Дружит с Clash fake-ip.** На прокси уходит имя хоста, а не адрес
  `198.18.x.x`, поэтому DNS резолвится на стороне выхода.
- **Встроенная проверка.** `rot test` подключается через каждый прокси,
  показывает задержку и IP выхода, помечает прокси, которые светят ваш IP,
  и может удалить нерабочие.
- **Любой формат списка.** `host:port`, `host:port:user:pass`, `socks5://…`,
  `http://…`. Положите файлы в `proxy/` - они импортируются сами.
- **Консоль на горячих клавишах.** Прокручиваемый список, проверка в фоне,
  внедрение, запуск и завершение процессов, фильтры и поиск. Клавиши работают
  и в английской, и в русской раскладке.
- **Без служб.** Один файл SQLite (`proxies.db`), без демонов и IPC, права
  администратора для обычных программ не нужны.

## Быстрый старт

Готовые бинарники лежат в `bin/`, ставить ничего не нужно.

<table>
<tr><th>Windows</th><th>Linux / macOS</th></tr>
<tr><td>

```powershell
cd C:\path\to\PerProcessProxy
.\run.cmd                      # консоль
.\run.cmd add socks5://1.2.3.4:1080
.\run.cmd test --prune
.\run.cmd on
.\run.cmd attach Telegram.exe
```

</td><td>

```sh
cd /path/to/PerProcessProxy
./run.sh                       # консоль
./run.sh add socks5://1.2.3.4:1080
./run.sh test --prune
./run.sh on
./run.sh launch "/path/to/app"
```

</td></tr>
</table>

Дальше выход можно менять в любой момент:

```sh
rot next          # следующий прокси
rot use 7         # прокси №7
rot auto 120      # ротация каждые 2 минуты
rot off           # пропускать всё напрямую
rot status        # что применено и какие процессы живы
```

Здесь `rot` - это `run.cmd` / `run.sh`. Подробный разбор всех команд, клавиш и
настроек - в **[инструкции](docs/USAGE.ru.md)**.

## Платформы

| Платформа | Как перехватывает | Подключение к запущенному | Статус |
|---|---|---|---|
| Windows x64 | `proxyinject.dll` внедряется через `inject.exe` | ✅ по pid или имени exe | готово |
| Linux x64 / arm64 | `proxyinject.so` через `LD_PRELOAD` | ❌ только запуск | готово |
| macOS arm64 / x64 | `proxyinject.dylib` через `DYLD_INSERT_LIBRARIES` | ❌ только запуск | готово |

Все платформы используют одни и те же `proxies.db`, `state/` и `logs/`, так что
одна консоль управляет всем.

> [!NOTE]
> На macOS системные программы под защитой SIP (`/usr/bin/curl`,
> `/usr/bin/python3`, …) и приложения с hardened runtime игнорируют
> `DYLD_INSERT_LIBRARIES`. Запускайте через прокси программы из Homebrew или
> собранные самостоятельно. Подробнее - в [инструкции](docs/USAGE.ru.md#macos).

## Ограничения

- **UDP не проксируется.** Он блокируется (кроме DNS), поэтому QUIC
  откатывается на TCP. Протоколы только на UDP работать не будут.
- **Публичные прокси в основном мёртвые.** Перед работой запускайте
  `rot test --prune`.
- **Владелец прокси видит TLS SNI**, а провайдер - объём и тайминги трафика.
  Скрываются только IP назначения и DNS.
- **Антивирус может ругаться на DLL.** Внедрение - тот же приём, что у
  вредоносов. Добавьте папку в исключения и внедряйтесь только в доверенные
  программы.
- **Программы с правами администратора** на Windows требуют консоль, тоже
  запущенную от администратора.
- **32-битные программы на Windows** не поддерживаются. Если нужно, соберите
  `inject32.exe` с `-target i386-windows-gnu`.

## Как это устроено

<details>
<summary>DLL для Windows</summary>

- 5-байтовые патчи `E9 rel32` на прологах функций `ws2_32` (`connect`,
  `WSAConnect`, `sendto`, `WSASendTo` и четыре резолвера). Заглушки лежат на
  странице в пределах ±2 ГБ от `ws2_32`.
- Каждая перехваченная функция реализована целиком, поэтому не нужны ни
  дизассемблер, ни трамплины.
- `ConnectEx` перехватывается подменой слота `WSAIoctl` в таблице импорта
  каждого загруженного модуля, проход повторяется каждые 3 с.
- Отдельная копия `ws2_32.dll` оставляет оригинальные резолверы доступными -
  на этом держится подстановка имён хостов для Clash fake-ip.
- Подпись базы прокси проверяется каждые 400 мс, при ротации живые сокеты
  обрываются.

</details>

<details>
<summary>Модуль для Linux / macOS</summary>

- Перехватывает `connect()` и `getaddrinfo()`. На Linux - подменой символов и
  `dlsym(RTLD_NEXT)`, на macOS - через секцию `__DATA,__interpose`.
- Сокет программы сам становится сокетом к прокси (`dup2`), отдельного потока
  для пересылки нет.
- SQLite вкомпилирован со скрытыми символами и не конфликтует с libsqlite3
  самой программы.

</details>

## Структура проекта

| Путь | Назначение |
|---|---|
| `bin/` | готовые бинарники: `rot*`, `inject.exe`, `proxyinject.{dll,so,dylib}` |
| `rust/` | исходники панели управления (`rot`) |
| `src/` | исходники DLL, инжектора и модуля для POSIX на C |
| `proxy/` | сюда кладутся списки прокси (`*.txt`) |
| `proxies.db` | список прокси и настройки (SQLite, создаётся при первом запуске) |
| `state/`, `logs/` | состояние и логи процессов, можно удалять |
| `tests/` | самопроверки и вспомогательные скрипты |
