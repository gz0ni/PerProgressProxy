## 1. Первый запуск

Откройте терминал в папке проекта и запустите консоль:

```powershell
.\run.cmd          # Windows
```

```sh
./run.sh           # Linux / macOS
```

При первом запуске рядом с лаунчером создаётся `proxies.db` - список прокси и
настройки. `rot doctor` покажет, что найдено: бинарники, база, ваш прямой IP и
слушает ли Clash.

> [!TIP]
> Любую команду можно выполнить разово, не открывая консоль:
> `rot status`, `rot list`, `rot next` и так далее.

## 2. Добавить прокси

Любым удобным способом.

**Файлом.** Положите любой `*.txt` в папку `proxy/`. Всё оттуда попадает в базу
при каждом запуске или сразу по команде:

```sh
rot import                     # вся папка proxy/
rot import my_list.txt         # один файл
```

**Из командной строки.**

```sh
rot add socks5://user:pass@1.2.3.4:1080 http://5.6.7.8:8080
```

**Из консоли.** Нажмите `v`, вставьте строки или ссылку `http(s)://` на список
и нажмите `F2`.

Поддерживаемые форматы строк:

```
socks5://user:pass@1.2.3.4:1080
socks4://1.2.3.4:1080
http://user:pass@1.2.3.4:8080
1.2.3.4:8080
1.2.3.4:8080:user:pass        формат WebShare
```

Голый `host:port` на портах 1080, 1081, 9050 и 9150 считается SOCKS5, на
остальных - HTTP. Поменять это можно так: `rot set default_scheme socks5`.
Дубликаты пропускаются.

## 3. Проверить прокси

```sh
rot test                       # проверить все: задержка и IP выхода
rot test --prune               # заодно удалить нерабочие
rot test --concurrency 64 --timeout 8
```

В консоли нажмите `t`: проверка идёт в фоне, результаты появляются в списке по
мере готовности. `f` оставит только рабочие.

> [!WARNING]
> Прокси с пометкой **same** возвращает ваш собственный IP. Он прозрачный и
> ничего не скрывает - удалите его.

## 4. Включить проксирование

По умолчанию проксирование **выключено**: программы с внедрённым модулем ходят
напрямую, пока вы его не включите.

```sh
rot on
```

В консоли - клавиша `o`. В шапке появится `PROXY: ON`.

## 5. Пустить программу через прокси

### Windows

```powershell
rot launch "C:\Program Files\App\app.exe"   # запустить сразу через прокси
rot attach 1234                             # уже запущенный процесс по pid
rot attach Telegram.exe                     # все запущенные копии по имени
rot watch Telegram.exe                      # подхватывать новые копии
```

В консоли: `l` - запуск, `a` - подключение (введите pid или имя exe).

> [!TIP]
> Запуск через `launch` или `watch` надёжнее, чем подключение потом: некоторые
> программы (Node, Electron, .NET) настраивают сеть при старте.

### Linux и macOS

Там работает только запуск: библиотека загружается при старте программы.

```sh
rot launch "/usr/bin/firefox --new-instance"
rot launch "/opt/homebrew/bin/curl -s http://checkip.amazonaws.com"
```

Программа продолжает работать после выхода `rot`. Остановить её - `kill <pid>`
или `rot kill <pid>`.

## 6. Переключение и ротация

| Что сделать | Команда | В консоли |
|---|---|---|
| следующий / предыдущий прокси | `rot next` | `n` / `p` |
| конкретный прокси | `rot use 7` | выбрать, `Enter` |
| ротация каждые 2 минуты | `rot auto 120` | `r` |
| остановить ротацию | `rot auto 0` | `r` |
| временно напрямую | `rot off` / `rot on` | `o` |

Каждый запущенный процесс с модулем подхватывает изменение примерно за секунду
и обрывает открытые соединения, так что программа переподключается уже через
новый выход.

## 7. Убедиться, что работает

- `rot status` показывает процессы с модулем, живы ли они и какой прокси
  используют.
- `logs/<pid>.log` пишет каждое соединение:
  `proxy 3 example.com via 1.2.3.4:1080`.
- Откройте в программе сайт проверки IP или запустите проверку:
  `rot launch "curl -s http://checkip.amazonaws.com"` (Linux).

## 8. Остановить

- `rot off` сразу переводит все процессы с модулем на прямое соединение.
- Закрыли программу - эффект закончился. В системе ничего не остаётся.
- `rot clean` убирает состояние завершённых процессов. Папки `state/` и `logs/`
  можно удалять в любой момент.

## Горячие клавиши консоли

Клавиши работают в обеих раскладках (`v` = `м`, `a` = `ф`, …).

| Клавиша | Действие |
|---|---|
| `↑` `↓`, `j` `k` | движение по списку |
| `PgUp` `PgDn`, `Home` `End` | постранично, в начало и конец |
| `Enter` | использовать выбранный прокси |
| `n` / `p` | следующий / предыдущий прокси |
| `v` | вставить прокси или ссылку на список; `F2` - применить, `Esc` - отмена |
| `a` | подключиться к процессу; `x` завершает выделенный |
| `l` | запустить программу через прокси |
| `t` | проверить все прокси в фоне |
| `o` | проксирование вкл / выкл |
| `r` | интервал авторотации |
| `/` | поиск |
| `f` | фильтр: все / рабочие / непроверенные / упавшие / same |
| `d` | удалить выбранный прокси |
| `c` | очистить состояние завершённых процессов |
| `?` | справка |
| `q` | выход |

Старая консоль с вводом команд тоже осталась: `rot console`.

## Настройки

Хранятся в `proxies.db` и применяются к запущенным процессам за секунду.
`rot config` - посмотреть, `rot set <key> <value>` - изменить.

| Ключ | По умолчанию | Значение |
|---|---|---|
| `enabled` | `0` | `1` - через прокси, `0` - напрямую |
| `fail_closed` | `1` | если все прокси упали - отказать в соединении, а не идти с вашего IP |
| `retry_next` | `1` | пробовать до 3 прокси подряд, прежде чем сдаться |
| `timeout_ms` | `10000` | таймаут подключения и рукопожатия |
| `rotate_sec` | `0` | интервал авторотации в секундах, `0` - вручную |
| `block_udp` | `1` | блокировать UDP, чтобы QUIC откатывался на TCP |
| `allow_dns_udp` | `1` | не трогать UDP-порт 53 |
| `hook_connectex` | `1` | перехватывать и `ConnectEx` (Node, Electron, .NET), Windows |
| `default_scheme` | `auto` | схема для голых `host:port`: `auto`, `socks5`, `socks4`, `http` |
| `current` | `0` | номер активного прокси, меняется через `rot use` / `next` |
| `log` | `1` | писать `logs/<pid>.log` |

Переменные окружения:

| Переменная | Что делает |
|---|---|
| `PPP_ROOT` | папка данных для `rot` (по умолчанию - папка проекта) |
| `PROXYINJECT_DIR` | папка данных для внедрённой библиотеки (`rot launch` ставит сам) |
| `PROXYINJECT_FORCE` | игнорировать базу и взять один прокси, например `socks5://127.0.0.1:1080` |
| `PROXYINJECT_LOG` | `1` / `0` поверх настройки `log` |

## macOS

Лаунчер использует универсальные `bin/rot-macos` и `bin/proxyinject.dylib`
(Apple Silicon и Intel).

**Что можно пустить через прокси.** macOS вырезает `DYLD_INSERT_LIBRARIES` у:

- системных программ под защитой SIP: всё в `/usr/bin`, `/bin`, `/System`,
  включая `curl`, `python3` и `arch`;
- приложений с hardened runtime без разрешения
  `allow-dyld-environment-variables` (большинство приложений из App Store и
  нотаризованных).

Утилиты из Homebrew, свои сборки и многие open-source приложения работают:

```sh
brew install curl
rot launch "/opt/homebrew/opt/curl/bin/curl -s http://checkip.amazonaws.com"
```

**Что не перехватывается.** Перехвачены только `connect()` и `getaddrinfo()`.
Приложения на Network.framework или `NSURLSession` (Safari и многие нативные
Cocoa-приложения) идут мимо них.

**Системный прокси.** Если Clash или другая программа включила системный прокси
macOS (его видно в `scutil --proxy`), многие приложения подключаются к
`127.0.0.1:7890`, а не к реальному хосту. Loopback не проксируется, поэтому
такой трафик идёт через Clash, а не через PerProcessProxy. Отключите
«использовать системный прокси» в приложении или сам системный прокси.

**Intel-приложения на Apple Silicon.** Работают под Rosetta с тем же dylib.
`arch -x86_64` - системная программа и тоже вырезает `DYLD_*`, поэтому
передавайте переменные через неё явно:
`arch -x86_64 -e DYLD_INSERT_LIBRARIES=... app`.

## Если что-то не так

| Симптом | Что проверить |
|---|---|
| IP не поменялся | `rot status`: `PROXY: ON`? Процесс в списке и жив? |
| Процесса нет в списке | библиотека не загрузилась: на macOS см. [выше](#macos); на Windows для программ с правами администратора запускайте консоль от администратора |
| Программа пишет «нет соединения» | `fail_closed=1` и все прокси упали. `rot test --prune` или `rot set fail_closed 0`, чтобы откатываться на прямое соединение (светит ваш IP) |
| В логе `proxy failed rc=-9/-10` | таймаут рукопожатия: прокси мёртв или заблокирован провайдером. Пробуется следующий |
| Часть запросов идёт мимо прокси | программа использует UDP/QUIC (блокируется, должна откатиться на TCP), Network.framework на macOS, или подключились слишком поздно на Windows - используйте `launch` / `watch` |
| Антивирус удаляет `proxyinject.dll` | добавьте папку проекта в исключения |

Логи: `logs/<pid>.log` для каждого процесса с модулем, `logs/ui-crash.log` -
падения консоли, `logs/launcher.log` - каждый запуск `run.cmd` на Windows.
